## Build & Run

```powershell
# Build and generate protobuf stubs
./mvnw compile

# Run server on port 9090 (default)
./mvnw spring-boot:run

# Run second server instance on port 9091 (for ForwardSayHello testing)
./mvnw spring-boot:run -Dspring-boot.run.profiles=server2

# Run tests
./mvnw test
```

## Testing with grpcurl

```powershell
# Unary
grpcurl -plaintext -d '{"name":"Alice"}' localhost:9090 HelloService/SayHello

# Server streaming
grpcurl -plaintext -d '{"name":"Alice"}' localhost:9090 HelloService/SayHelloStream

# Forward (9090 → 9091); requires both servers running
grpcurl -plaintext -d '{"name":"Alice"}' localhost:9090 HelloService/ForwardSayHello

# Test exception handling
grpcurl -plaintext -d '{"name":""}' localhost:9090 HelloService/SayHello      # INVALID_ARGUMENT
grpcurl -plaintext -d '{"name":"unknown"}' localhost:9090 HelloService/SayHello  # NOT_FOUND
```

## Architecture

### Proto → Java code generation

`.proto` files in `src/main/proto/` are compiled by `protobuf-maven-plugin` during `mvn compile`. The plugin invokes `protoc` + `protoc-gen-grpc-java` and places generated stubs under `target/generated-sources/`. The generated package is `com.example.javagrpc.grpc`.

### Version management

`grpc-bom:1.75.0` is declared in `<dependencyManagement>` to override transitive gRPC versions pulled in by `grpc-server-spring-boot-starter:3.1.0.RELEASE`. Without this, the runtime jars are too old for the 1.75 stubs generated by `protoc-gen-grpc-java`.

### Service layer

`HelloServiceImpl` extends the generated `HelloServiceGrpc.HelloServiceImplBase` and is registered as a gRPC service via `@GrpcService`. Three RPC methods:

| Method | Pattern | Notes |
|---|---|---|
| `SayHello` | Unary | Throws domain exceptions; handled by `@GrpcAdvice` |
| `SayHelloStream` | Server streaming | Pushes 5 responses then completes |
| `ForwardSayHello` | Unary (proxy) | Calls 9091 via injected `@GrpcClient` stub; propagates upstream deadline |

### Exception handling

`GlobalGrpcExceptionHandler` (`@GrpcAdvice`) maps domain exceptions to gRPC Status codes centrally — service methods can throw plain Java exceptions without manually calling `responseObserver.onError()`.

| Exception | gRPC Status |
|---|---|
| `HelloNotFoundException` | `NOT_FOUND` |
| `HelloBadRequestException` | `INVALID_ARGUMENT` |
| `Exception` (catch-all) | `INTERNAL` |

### Deadline propagation in ForwardSayHello

```
caller ──(deadline)──▶ 9090:ForwardSayHello ──(same deadline)──▶ 9091:SayHello
```

`Context.current().getDeadline()` reads the deadline the caller set. If present it is forwarded as-is via `.withDeadline(upstreamDeadline)` so the entire chain shares one absolute timeout. If absent (e.g. grpcurl with no deadline), a 3-second fallback is applied.

### Two-server setup

`application.yaml` sets the default port to 9090. `application-server2.yaml` overrides it to 9091. Run both simultaneously to exercise `ForwardSayHello`.

### Key dependency notes

- `javax.annotation-api:1.3.2` — required because Java 21 removed the `javax` namespace but the gRPC code-gen still emits `@javax.annotation.Generated`
- `@GrpcClient` injection is done at runtime via reflection; IDE false-positive "never assigned" warnings on those fields are suppressed with `@SuppressWarnings("unused")`
